01計畫總覽

用同一套 AI 工具（Claude Code＋MCP），在 Godot、Unity、Unreal 做出同一款 2D 射擊遊戲，記錄 AI 在三款引擎上能幫多少忙、在哪裡卡住，最後整理成給學弟妹照著做的教學手冊。

研究動機、問題與目標

本社群從學生團隊做遊戲的實際需求出發：AI 已經能寫程式、生美術和音效，但這些東西放進遊戲引擎時會遇到什麼問題、要怎麼解決，還沒有適合學生的整理。我們選了三款常見的跨平台引擎做比較：

  • Godot：開源、超輕量，電腦硬體需求低。
  • Unity：大專院校教學主力，C# 的學習資源最多。
  • Unreal Engine 5：業界高階畫面規格，但藍圖與 C++ 對純文字的 AI 來說門檻較高。

研究問題　同一份規格、同一個 AI，放到三款不同的遊戲引擎，AI 能幫多少忙？哪裡最容易卡住？學生團隊該怎麼選引擎？

為了回答這個問題，我們在學生筆電上實際走過三遍，並把每一步量化記錄下來。五個目標與目前的成果如下：

#目標做法成果
1驗證 AI 工作鏈在學生設備上的可行性在學生筆電裝好三款引擎與 Claude Code＋MCP，完成同規格原型並匯出 Windows 執行檔三款原型皆可在 Windows 執行
2實測 AI 代碼除錯成本與模型相容痛點每個模組記下首次通過、追問次數、人工修補次數與錯誤類型首次通過：Unity 4/6、Unreal 4/6、Godot 3/6
3深化多模態生成式 AI 開發能力先做風格測試再量產共用素材，保存提示詞共用素材包 v4.8：11 個場景、140 格特效、46 個音效
4產出「學生 AI 遊戲開發實務指引」歸納 AI 踩坑與報錯處理，編成入門教材與踩坑卡入門教材 25 頁、踩坑卡 15 則、提示詞 18 則（引擎 15 則、美術與音效 3 則）

02前期研究

AI 遊戲開發案例拆解

三款引擎各挑 2 個公開的 AI 輔助開發案例，從工具鏈、流程、引擎串接、瓶頸四個面向拆解，再寫出對本計畫的啟示。

引擎案例工具鏈對我們的啟示
Unity官方 Unity MCP 修改 TPS 遊戲Claude Code＋官方 Unity MCP（編輯器內建 MCP 已停用，本計畫改用 MCP for Unity）任務切小，逐項記錄成功與否
Project Aegis 開發日誌Claude Code＋MCP for Unity可加入「需手動介入次數」作為指標
GodotFlappy Bird（headless 模式）Codex CLI＋Godot --headless純文字專案適合 CLI 型 AI 與自動化驗證
BlockBlast RPG（15 天）Claude＋Godot手感與平衡仍要靠人反覆調整
UnrealEpic 官方示範（UE 5.8）在 UE 內使用 Claude Code官方已把 AI 編碼助手納入引擎流程
AI 生成 3D 資產匯入 UE5文字／圖片生成 3D → 重拓撲 → 匯入2D 原型不直接適用，只作工時背景對照
  • Unity：MCP 讓 AI 能直接操作編輯器，場景與 prefab 都可以由 AI 完成；但案例用的內建 MCP 已被 Unity 停用，穩定度要自己驗證。
  • Godot：語法簡單、檔案是純文字，容易做自動化測試；AI 可能捏造函式或給出 Godot 3 舊語法，提示詞要寫明版本。
  • Unreal：官方在 AI 整合上投入最明顯，但公開的獨立開發者案例少，資料多來自官方與廠商。

總結論　AI 能加速串接與寫程式，但遊戲手感、平衡與驗證仍要靠人。Unity 的 MCP 可以直接操作編輯器，Godot 的命令列與自動測試最順，Unreal 官方投入多但案例少。

因此本計畫的做法
做法說明
任務切小並記錄把原型拆成模組，每個模組記錄首次通過、追問次數與人工修補次數
讓錯誤回到 AI透過 MCP 讓 AI 自己執行、讀錯誤；錯誤能否自動回傳也列為比較指標
提示詞寫明版本註明三款引擎的版本，降低舊語法與捏造函式的風險
分清 AI 與人的工作分欄記錄 AI 負責與人負責的項目

案例資料多為開發者自述，屬於單一案例經驗，不是對照實驗；以上比較只限本社群的設備、成員經驗與指定任務，不外推為引擎優劣。

結論與建議

研究問題是「學生團隊該怎麼選引擎」。依本次預演，三款引擎都能用同一套 AI 工具做出同規格原型，差別在 AI 卡住的地方：

引擎AI 卡住的地方適合的團隊
GodotAI 開發時間最短（73 分），但規格以外的介面、敵人動作與手感要靠人補（人工修補 4 次）電腦不強、想快速做 2D 原型
Unity修改全部由 AI 完成（人工修補 0 次），但追問最多（5 次），要注意 Unity 6 改名的 API 與背景不編譯需要大量教學資源、想長期學習
Unreal內建 MCP 的準備步驟最少，但 MCP 還不能建關卡、匯入字型與音效，M1 花了 35 分；AI 寫 C++ 時要會處理編譯錯誤電腦夠力、需要高階畫面

共同結論　AI 能做出可運作的模組，但「好不好玩」要靠人試玩判斷。驗收標準要加入試玩項目，每個模組都要匯出執行檔實測。

以上比較只限本社群的設備、成員經驗與指定任務，不外推為引擎優劣。

各引擎手冊

引擎Godot 4.7.2-stable 標準版（GDScript），相容性（Compatibility）算繪器
MCPgodot-ai 4.3.1（外掛與伺服器同版本，寫死在指令裡，每台電腦才一致）
為什麼鎖 4.7.2目前最新穩定版；godot-ai 4.x 只支援 4.7 以上。4.8 只有 beta，實戰前不要升級，用 beta 存過的專案回 4.7.2 會被警告降版
從零接通 godot-ai（12 步）
  1. 執行 claude auth status 確認是 max 方案，再執行 claude -p "回覆 OK"，有回覆才算能用（只看 status 不夠）。
  2. 安裝 uv：powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/0.13.5/install.ps1 | iex"，重開 PowerShell。
  3. Godot 解壓到英文無空格路徑；建專案，照上表設定，建 Main 場景（Node2D）並設為主場景。
  4. 確認有 .gitignore、.gitattributes，git init 後 commit 一次。
  5. 第一次啟用外掛前關遙測：[Environment]::SetEnvironmentVariable("GODOT_AI_DISABLE_TELEMETRY", "true", "User")。
  6. 到 GitHub hi-godot/godot-ai 的 v4.3.1 下載 godot-ai-v4-plugin.zip（同頁較大的 godot-ai-plugin.zip 是遷移工具，不是外掛本體），用 Get-FileHash 比對雜湊值。
  7. 把 zip 裡的 addons 資料夾放到專案根目錄，確認有 addons\godot_ai\plugin.cfg。
  8. 專案設定 → 外掛程式勾選 Godot AI，等輸出面板出現 MCP | authenticated with server。
  9. 在專案資料夾登記 MCP：claude mcp add --scope project godot-ai -- uvx godot-ai==4.3.1 attach --port 8000 --ws-port 9500 --disable-telemetry，再 commit。
  10. 先開 Godot，再在專案資料夾輸入 claude（橋接型順序不能反），信任資料夾並核准 godot-ai。
  11. 輸入 /mcp 看到 godot-ai connected（47 個工具），再請它「讀目前的場景樹」，回覆 Main (Node2D) 才算真的接通。
  12. 把 CLAUDE.md 放進專案根目錄，/exit 後重開 claude 才會生效。
CLAUDE.md 範本 
# 專案規則（Null Hunter／Godot 組）
- 引擎：Godot 4.7.2 標準版；Compatibility；1280×720，stretch canvas_items、aspect keep；貼圖篩選 Nearest；max_fps 60
- 用 godot-ai MCP 建節點、改屬性、掛腳本、設 Input Map、執行場景
- 我是新手：做完列出你用 MCP 做的操作，和我要手動確認的步驟

## 一律用 Godot 4 寫法
- CharacterBody2D、@export、@onready、await、instantiate()、訊號.connect(方法)
- 座標 y 向下為正；角度用弧度

## 專案約定
- 輸入只用 Input Map：move_left/right/up/down、shoot、confirm、pause
- 碰撞用圓形；子彈和敵人用 Area2D；快速子彈要做掃掠圓形判定
- 子彈加到 current_scene，不要當玩家子節點；飛出畫面就 queue_free()
- 分數放在 autoload GameState；HUD 用 CanvasLayer＋Label
- 規格數值寫成 @export，不可自行更改

## 工作方式
- 只做指定模組、只改允許的檔案；不要直接用文字改 .tscn
- 寫完先用 MCP 執行、讀錯誤，修到沒錯再回報
